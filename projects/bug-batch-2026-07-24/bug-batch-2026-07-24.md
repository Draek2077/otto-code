### ✅ Ctrl+S / Cmd+S saves in the editor (acute symptom of #8)

"Control-S doesn't save."

Root cause: `Cmd/Ctrl+S` is globally bound to **open search sidebar** with no
`editable` guard, so it intercepts the keystroke before CodeMirror's own
`Mod-s` → Save handler (`editor-core.ts:359`) runs. Added `editable: false` to
those two bindings so a focused text surface keeps Cmd+S for Save; `Cmd+Shift+F`
still opens search.

Extended to the user's clarified model: **editor shortcuts win on overlap;
non-overlapping Otto shortcuts keep working while editing.** The mechanism is
`editable: false` on each colliding general binding — done for Save (Cmd/Ctrl+S,
vs open-search) and Find (Cmd/Ctrl+F, vs open-files-sidebar). Go-to-line
(`Mod-g`) has no Otto collision. These are the only overlaps in today's editor
shortcut set.

- `packages/app/src/keyboard/keyboard-shortcuts.ts` — `sidebar-open-search-*` and
  `sidebar-open-files-*` bindings now carry `editable: false`.
- Verified: `keyboard-shortcuts.test.ts` (71 pass).
- **Superseded 2026-07-25 by #8's File Editor section**, which generalizes this:
  `editor.find` is a focus-scoped registry binding that outranks the `Mod+F` file
  finder in the editor, so no general binding needs a guard for the overlap. The
  `editable: false` on the `Mod+F` pair survives for the OTHER scopes (composer,
  plain text fields), where there is no editor binding to hand the combo to.

### ✅ Darker editor background (#1)

No theme token sits below `surface0`, so the editor well is derived from it:
`deepenEditorSurface()` scales `surface0` toward black (hue-preserving, so tinted
palettes stay on-tint) by a luminance-aware amount — dark themes deepen ~0.25,
light ~0.035. Only the code area deepens — a separate `gutterBackground` spec
field keeps the gutter (and toolbar/status) at `surface0`.

- `packages/app/src/editor/editor-theme.ts`, `editor-contract.ts`, `editor-core.ts`.

### ✅ Git "push" disabled after commit — GitHub only (#2)

The push policy was never wrong (`git/policy.ts:576` `canPush`) — it was being fed
a stale `aheadOfOrigin: 0`. The hosting PR-status poll refreshes only PR/check
state, but `checkout_status_update` has no PR-only shape, so its re-broadcast
rebuilt a **whole** checkout status from the last git measurement and published it
as news. Right after a commit that echo landed on top of the freshly fetched
`aheadOfOrigin: 1` and muted Push. Bitbucket polls far more slowly (30s/180s, per
`docs/git-providers.md:40`), so it rarely hits the post-commit window — the bug
looked GitHub-specific but the path is shared.

**Server (the real fix)** — the poll no longer passes its git block off as fresh:

- `workspace-git-service.ts` — snapshot emissions now carry a
  `WorkspaceGitSnapshotMeta { prStatusOnly }`; `rememberGitHubSnapshot` (the poll's
  only caller) sets it. `WorkspaceGitRuntimeSnapshot.gitLoadedAtMs` records when
  the git block was measured, and is excluded from the emission fingerprint so a
  timestamp alone never looks like a change.
- `checkout/status-projection.ts` — projects `gitLoadedAtMs` onto the wire as
  `gitStateAt`.
- `session/checkout/checkout-session.ts`, `workspace-git-observer-service.ts`,
  `session.ts` — plumb the meta through to `checkout_status_update.prStatusOnly`.

**Client (defense in depth)** — `git/checkout-status-cache.ts` gained
`carriesFreshGitState`: skip the git-status write (and its dirty-state reaction)
when the push is `prStatusOnly`, or when its `gitStateAt` predates the cached one.
A monotonic stamp beats per-field rules here — every git-tracking field is written
by one producer and moves as a unit, and all of them (`aheadOfOrigin`,
`behindOfOrigin`, `isDirty`) can legitimately regress, so there is no per-field
rule to write. `prStatus` from the same push is still applied; it is the one thing
the poll actually refreshed.

**Protocol** — two additive optional fields, both `COMPAT(...)`-tagged in
`messages.ts`: `gitStateAt` on the shared status payload and `prStatusOnly` on the
update metadata. Absent on old daemons → the pre-existing apply-everything
behavior, which is the only correct reading of a payload with no freshness signal.

Tests: `checkout-status-cache.test.ts` (16), `workspace-git-service.test.ts` (19 +
1 skipped — includes a poll-emits-PR-only case), `checkout-session.test.ts` (31).
The two new client cases were verified to fail without the guard.

### ✅ #8 — Full keyboard-shortcut review + a "File Editor" section

"Shortcuts are not right for file editors… not Dev friendly." Plus the direction:
_a new "File Editor" settings section holding editor 'duplicates' that OVERRIDE
the general Otto shortcuts while the editor is focused._

**FIXED 2026-07-25.** All three pieces shipped: a **File Editor** section in
`SHORTCUT_BINDINGS` (save, find, go to line, go to definition + F12 alias, find
references `Shift+F12`, rename symbol `F2` — the last two had no key at all
before, only a menu item); `bindingSpecificity` in the matcher, so a binding that
names the focused surface beats an unscoped one on the same combo; and
`editor/editor-key-bindings.ts` turning the user's effective File Editor rows
into the CodeMirror keymap, mounted in its own `Compartment` so a rebind lands
without a remount.

The override is per combo, which is the user's model exactly: `Mod+B` is Go to
definition in the editor and the left-sidebar toggle everywhere else, while
`Ctrl+K` opens the command center in both. The interim `codeEditor: false` guard
noted above is **deleted** — a hardcoded guard cannot follow a rebind, so moving
Go to definition off `Mod+B` used to leave that combo dead in the editor.
