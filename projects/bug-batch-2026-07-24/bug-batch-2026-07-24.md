### ✅ Ctrl+S / Cmd+S saves in the editor (acute symptom of #8)

"Control-S doesn't save."

Root cause: `Cmd/Ctrl+S` is globally bound to **open search sidebar** with no
`editable` guard, so it intercepts the keystroke before CodeMirror's own
`Mod-s` → Save handler (`editor-core.ts:359`) runs. Added `editable: false` to
those two bindings so a focused text surface keeps Cmd+S for Save; `Cmd+Shift+F`
still opens search.

Extended to the user's clarified model: **editor shortcuts win on overlap;
non-overlapping Otto shortcuts keep working while editing.** The mechanism is
`editable: false` on each colliding general binding — done for Save (Cmd/Ctrl+S,
vs open-search) and Find (Cmd/Ctrl+F, vs open-files-sidebar). Go-to-line
(`Mod-g`) has no Otto collision. These are the only overlaps in today's editor
shortcut set.

- `packages/app/src/keyboard/keyboard-shortcuts.ts` — `sidebar-open-search-*` and
  `sidebar-open-files-*` bindings now carry `editable: false`.
- Verified: `keyboard-shortcuts.test.ts` (71 pass).
- **Note:** the registry-driven "File Editor" section (#8) generalizes this so new
  editor shortcuts get the override for free — see the plan doc.

### #2 — Git "push" disabled after commit, GitHub only (Bitbucket fine)

Root-caused. The push policy itself is **provider-neutral and correct**
(`git/policy.ts:576` `canPush`); the bug is stale data feeding it.

- After a commit, the client refetches a correct status (`aheadOfOrigin ≥ 1` →
  push enabled). But a new commit changes PR checks, so GitHub's PR-status poll
  fires `onStatus` within seconds and re-broadcasts a **full**
  `checkout_status_update` built from `target.latestGit`
  (`workspace-git-service.ts:1776-1822` → `checkout-session.ts:401-422`). If that
  re-emit wins the race against the git-only refresh, it ships the _pre-commit_
  git block (`aheadOfOrigin: 0`); the client overwrites its good status
  unconditionally (`checkout-status-cache.ts:36-51`) → push muted.
- Bitbucket's poll is far quieter (30s/180s, per `docs/git-providers.md:40`) so it
  doesn't re-broadcast in the post-commit window → looks GitHub-specific.
- **Fix (preferred, server):** the PR-status poll must not publish git-tracking
  state — either refresh `latestGit` before `combineSnapshot`, or emit a
  PR-status-only update from the poll.
- **Fix (defense-in-depth, client):** in `applyCheckoutStatusUpdateFromEvent`,
  don't let a push downgrade `aheadOfOrigin`/`behindOfOrigin` vs the cached value
  when it carries no newer git generation (mirror the existing
  `reconcileCheckoutStatusWithUncommittedDiff` guard).

### #5 — "Explain this to me" over an editor selection, with AI

selection.

- Entry point: the editor already exposes `controller.getSelection()`
  (`editor-core.ts:501`) and the git-history toolbar button proves the
  selection-aware-toolbar pattern. Add an "Explain selection" action (toolbar
  button and/or right-click — note Electron's context-menu caveat at
  `file-tab-pane.tsx:1005`).
- Needs a daemon capability: a one-shot "explain this snippet" prompt to the
  active provider, streamed into a side panel or sheet (not the main chat). Must
  be provider-neutral (Claude + openai-compat + others) per the fork's charter.
- **Open questions:** where the answer renders (sheet vs side pane vs ephemeral
  bubble); whether it seeds a real chat turn or a throwaway query; how much file
  context to include around the selection.
