# Otto Glossary

Authoritative terminology. UI label wins. Don't invent synonyms; use what's here.

- **Project** - Logical grouping of workspaces sharing a git remote (or main repo root). UI: "Project" / "Add project". Code: `ProjectSummary` (`packages/app/src/utils/projects.ts`), `projectKey` (`packages/server/src/server/workspace-registry-model.ts`). Forbidden: "Repo", "Repository" as UI label.
- **Solution** - A .NET solution file (`.sln` or `.slnx`) and the organisation it describes: solution folders, the projects inside them, configurations and platforms. Also the name of the Files module's second lens, which renders it. **A .NET project is not an Otto Project** - Project (above) is a grouping of workspaces sharing a git remote, and the two appear on screen at the same time, so a `.csproj` node is called by its own name and is typed `solutionProject` in code. UI: "Solution" (the view switcher in the Files tab), "Microsoft .NET Solution Management" (the Daemon → Code setting). Code: `SolutionRef`, `SolutionTreeProject` (`packages/protocol/src/messages.ts`), `solution-model/` (`packages/server/src/server/`). See [solution-view.md](solution-view.md). Forbidden as UI labels: "Project view", "Solution project" - and never "project" alone for a `.csproj`.
- **Workspace** - One concrete `cwd` on one daemon, with git state; belongs to exactly one project. Its `id` is opaque workspace identity; its `cwd` is the filesystem directory. UI: "Workspace". Code: `WorkspaceDescriptorPayload` (`packages/protocol/src/messages.ts`). Don't confuse with: Branch (one branch can back many workspaces via worktrees). Forbidden: "Folder", "Directory" as UI label.
- **Archive workspace** - Removes one workspace from active use and archives everything it owns. UI and app shortcuts always say "Archive workspace", regardless of backing. The daemon leaves ordinary directories intact and removes an Otto-owned worktree only when no active workspace still references it. CLI/MCP **archive worktree** is a separate lower-level operation that archives every workspace on that worktree.
- **Workspace kind** - `"directory" | "local_checkout" | "worktree"`. The git-derived, persisted property of a workspace, used across its lifetime (archive safety, sidebar, grouping). Derived from the cwd's git reality (`deriveWorkspaceKind`, `packages/server/src/server/workspace-registry-model.ts`), not stored from a user choice. Code: `PersistedWorkspaceKind` (`packages/server/src/server/workspace-registry-model.ts`). Don't confuse with **Isolation** (the create-time intent).
- **Isolation** - Create-time choice for a new workspace: reuse the existing checkout (**Local**) or cut a dedicated git worktree (**New worktree**). A transient setup input, also remembered as a create-form preference; it is not a workspace property. UI: "Isolation" control on the New Workspace screen. Code: `isolation` (`"local" | "worktree"`), `useWorkspaceIsolation` (`packages/app/src/screens/new-workspace-screen.tsx`); persisted as `FormPreferences.isolation` (`packages/app/src/create-agent-preferences/preferences.ts`). Distinct from **Workspace kind**, which is the git-derived property the intent produces (Local → `local_checkout` or `directory` by git-ness; New worktree → `worktree`). On the wire it is the create request's `source.kind` (`directory | worktree`, `packages/protocol/src/messages.ts`).
- **Chat** - The **wrapper** the user interacts with and views through: the durable conversation surface with a tab, a title, a timeline, and an archive gesture. This is the conceptual unit users manipulate - you archive, rename, and close a **chat**. Historically this was called an "agent" throughout the codebase and docs; that usage is deprecated in prose. UI: "chat" everywhere on the conversation surface ("New chat", "rename chat", "chat not found"). Code identifiers stay historical and are **not** renamed: `AgentSnapshotPayload` (`packages/protocol/src/messages.ts`), `AgentManager`, `agentId`, i18n keys `newAgent`, shortcut id `new-agent`, testIDs. See [chat-lifecycle.md](chat-lifecycle.md). Forbidden as UI labels: "Agent" for the conversation surface, "Task", "Job", "Run".
- **Agent** - The **AI session running inside a chat** - one provider, one model, one effort, one running process, one timeline. Not the wrapper. You stop an **agent**; you archive the **chat** that hosts it. UI still says "Agent" in technical/settings contexts where the AI session genuinely is the subject (providers, personalities, permissions, "Agent personalities"). Code: `AgentSnapshotPayload` (`packages/protocol/src/messages.ts`). Don't confuse with **Chat** (the wrapper) - using "agent" to mean the conversation surface is the specific error this entry exists to prevent.
- **New chat** - The action that creates a new **chat** in a workspace (which in turn hosts an agent session). UI: "New chat" everywhere (command center, workspace header, tab actions/fallbacks, draft panel). Forbidden as UI labels: "New agent", "Create agent". Code identifiers stay historical: i18n keys `newAgent`, shortcut id `new-agent`, testIDs.
- **Add to chat** - The action that attaches content to the composer as an attachment pill: files and folders (file explorer, Changes context menu, File Editor toolbar, `@` mention), a selected range (File Editor right-click, labelled "Add selection to chat"), search hits and lines (project search), and PR comments/reviews/threads/check logs (PR panel). One label for all of them; the inverse is "Remove from chat". Forbidden as UI label: "Add to context". Code identifiers stay historical: i18n keys `addToContext`/`removeFromContext`, attachment kind `file_context`, store `useWorkspaceAttachmentsStore` (`packages/app/src/attachments/workspace-attachments-store.ts`); ids come from `buildFileContextAttachmentId` (`packages/app/src/attachments/file-context.ts`) so producers cannot spell one target two ways.
- **Daemon** - Local Otto server process; identified by `serverId`. UI: "Daemon" (system contexts only). Code: `serverId` in `ServerInfoStatusPayloadSchema` (`packages/protocol/src/messages.ts`), `DaemonClient` (`packages/client/src/daemon-client.ts`).
- **Host** - Client-side connection profile pointing at a daemon; bundles one or more `HostConnection`s. UI: "Host" / "Add host" / "Switch host". Code: `HostProfile` (`packages/app/src/types/host-connection.ts`). Forbidden: "Connection" (means `HostConnection`, not host).
- **Host badge** - The item on a sidebar workspace row's meta row naming which host that workspace lives on. Three things gate it, and they compose as a lattice rather than competing: the sidebar must span more than one host (automatic), **Show → Host** in the sidebar's display preferences must be on (global, all hosts at once), and then that host's own display mode decides _how_ it draws: **Name** / **Icon only** / **Hidden**. Name, color, and display mode are per-host, per-device, and live client-side on `HostProfile.appearance`; nothing about it reaches the daemon. Never add a fourth way to hide it. UI: the "Appearance" group on a host's settings page, and the "Show" submenu in the sidebar's display preferences. Code: `selectHostBadges` (`packages/app/src/hosts/appearance.ts`) takes the first two as its `enabled` input; `WorkspaceMetaRow` (`packages/app/src/components/sidebar/workspace-meta-row/index.tsx`) draws it. Don't confuse with **Status pill**, which reports state rather than identity.
- **Project host entry** - One row in a project for a single (project, daemon) pair, aggregating that daemon's workspaces in the project. Internal. Code: `ProjectHostEntry` (`packages/app/src/utils/projects.ts`). Don't introduce "Checkout" as a synonym.
- **Placement** - One workspace's relationship to its project (projectKey, projectName, git checkout snapshot). Internal. Code: `ProjectPlacementPayload` (`packages/protocol/src/messages.ts`).
- **Branch** - Plain git branch. UI: "Switch branch". Code: `currentBranch` in `WorkspaceGitRuntimePayloadSchema` (`packages/protocol/src/messages.ts`); `BranchSwitcher` (`packages/app/src/components/branch-switcher.tsx`).
- **Worktree** - Otto-managed git worktree (`~/.otto/worktrees/{name}`); also a `workspaceKind` value. UI: CLI + `otto.json` keys (`worktree.setup`, `worktree.teardown`) only. Code: `ProjectCheckoutLiteGitOttoPayload` (`packages/protocol/src/messages.ts`); CLI `otto worktree` (`packages/cli/src/commands/worktree/index.ts`). Forbidden: "Checkout" as a synonym.
- **Repository / Remote** - Internal git inputs (`remoteUrl`, `mainRepoRoot`) used to derive `projectKey`. No UI label.
- **Git provider** (a.k.a. git hosting provider / forge) - The service backing a workspace's PR and issue features: **GitHub** or **Bitbucket Cloud**. Configured once per host under Host settings → Workspaces → "Git providers"; a workspace's provider is auto-derived from its remote (`github.com` → GitHub, `bitbucket.org` → Bitbucket Cloud). UI: "Git providers". Code: `GitHostingProviderId` (`packages/protocol/src/git-hosting.ts`), `GitHostingService` + `resolver.ts` (`packages/server/src/services/git-hosting/`). See [git-providers.md](git-providers.md). Forbidden: "GitHub" as the generic label now that Bitbucket exists.
- **Directory-backed surface** - A right-sidebar surface whose content is determined by the workspace's `cwd`, so two workspaces on the same directory see identical content: git diff/status, PR info (GitHub or Bitbucket Cloud, resolved from the cwd's remote), file preview/explorer contents. Keyed by `(serverId, cwd)`, never `workspaceId`. See [architecture.md](architecture.md#right-sidebar-boundary-directory-backed-vs-workspace-owned).
- **Workspace-owned state** - Per-workspace state that never leaks to a same-`cwd` sibling: tabs, chats, terminals, panes, title, plus review drafts, diff-mode overrides, composer attachments, and file-explorer open/expand state. Keyed by `workspaceId` (`cwd` only as a fallback for old payloads). See [architecture.md](architecture.md#right-sidebar-boundary-directory-backed-vs-workspace-owned).
- **Workspace status bucket** - Aggregate activity signal for a workspace row, computed strictly per `workspaceId`: an agent or terminal contributes only to the workspace it carries, and a terminal with no `workspaceId` contributes to nothing. Same-`cwd` siblings do not share status buckets (`applyTerminalContributions`, `packages/server/src/server/workspace-directory.ts`). Only git facts (branch, diff, dirty, PR) fan out across same-`cwd` workspaces - see **Directory-backed surface**.
- **Agent session** - Long form of **Agent**: one running instance of an AI session inside a chat (one provider, one model, one cwd, one timeline). Use when "agent" alone would be ambiguous. The **chat** is the wrapper it runs inside and the thing that opens as a tab - not this. Code: `AgentSnapshotPayload` (`packages/protocol/src/messages.ts`).
- **Session** - Two senses: (a) per-client connection to a daemon, internal; (b) user-facing agent session, see **Agent session**. Code: `Session` (`packages/server/src/server/session.ts`) for (a). Don't confuse with: provider-side agent session log.
- **Profile** - Internal name for the persisted shape of a host. Code: `HostProfile` (`packages/app/src/types/host-connection.ts`). Never user-facing. Several other things are called "profile" in this codebase, so always qualify: **Agent profile**, **Terminal profile**, **Model profile**, **Prompt & template profile**, and the provider aliases in [custom-providers.md](custom-providers.md). Bare "profile" is forbidden in UI copy.
- **Agent profile** - Retired as a separate concept. Paseo's launch bundle and Otto's Personality converged onto one stored template: `AgentProfile` is the code name, **Personality** is the only user-facing label, and `daemon.agentProfiles` is the one roster. There is no second editor, no `list_profiles` tool, and no drift tracking. Use **Personality** in any prose a human or a model reads, and `profile` only in code. See **Personality** below.
- **Terminal profile** - A named shell command a terminal can launch. Stored host-wide in daemon config as `terminalProfiles`. UI: "Terminal profiles". Code: `TerminalProfile` (`packages/protocol/src/messages.ts`), `resolveTerminalProfiles` (`packages/protocol/src/terminal-profiles.ts`). Also selectable as a New Workspace launch target, where the alternative is the chat agent. Don't confuse with **Script**, which is a project-declared or discovered command rather than a host-wide shell.
- **Provider** - Agent backend (Claude Code, Codex, Copilot, OpenCode, Pi, OMP). UI: "Provider". Code: `ProviderSnapshotEntry` (`packages/protocol/src/messages.ts`).
- **Model** - A specific LLM offered by a provider. UI: "Model" / "Select model". Code: `AgentModelDefinition` (`packages/protocol/src/messages.ts`).
- **Model profile** - The per-model launch and VRAM settings for Otto Brain: context multiplier and context, KV cache types, flash attention, vision/components, reasoning budget, GPU layers, and parallel slots. It is the settings shape that calibration evaluates. Code: `Profile` (`packages/brain/src/config/schema.ts`), `BrainProfile` (`packages/protocol/src/messages.ts`). Don't confuse with **Prompt & template profile**, which formats requests and does not itself affect VRAM. Forbidden: "Hosting profile", "tuning", and bare "profile" when the referent is ambiguous.
- **Prompt & template profile** - A named, Brain-owned, model-family-bucketed record containing a Jinja chat template, optional template kwargs, and an optional system-prompt addendum. UI: "Prompt & template" in model settings and "Prompt & template profiles" in its dialog. A model profile can inherit its family's default, turn profiles off, or select a custom one. Code retains the legacy wire and persisted names `HostingProfile`, `hostingProfileId`, `hostingProfileMode`, and `familyHostingProfileIds` until a compatibility migration replaces them. Don't confuse with **Model profile**. Forbidden: "Hosting profile" and bare "profile" when the referent is ambiguous.
- **Personality** - A named, reusable per-host agent template binding a provider→model, effort, mode, feature values, prompt, one or more **roles**, notes, and an identity (name, spinner colors, voice). The ergonomic "who does the work" pick, shown atop every model picker. Bound by stable `id`, never `name`; a picker or tool may accept the display name, but what gets stored is the id. **Code says profile, every user-facing string says Personality** - that split is deliberate, so `AgentProfile` and "Personality" name the same thing. UI: "Agent personalities" (Host settings → Agents). Code: `AgentProfile`, `PROFILE_ROLES` (`packages/protocol/src/messages.ts`); role/availability/lookup helpers in `packages/protocol/src/agent-profiles.ts`; resolution/snapshot in `packages/server/src/server/agent/agent-profiles.ts`. MCP: `list_agent_profiles`, and `create_chat`'s `agentProfile` field. The MCP surface says agent profile rather than Personality because the tool catalog is read by models, not people. See [agent-personalities.md](agent-personalities.md). Don't confuse with **Provider** (a Personality selects one), **Mode** (a Personality carries a default one), or the other things this codebase calls "profile" (see **Profile**).
- **Role** - One of 11 tags a Personality carries, in three groups: the **surfaces** (Chatter, Artificer, Scheduler), the **thinking specialists** (Researcher, Planner, Judger, Advisor), the **making specialists** (Coder, Designer, Writer), and the lone conductor (Orchestrator). A role gates which pickers the Personality appears in. **It is not a permission gate**: every agent keeps the same tools, and enumerating or spawning Personalities is open to all of them. Roles fall into two **tiers** that drive guidance only - a Personality carrying any coordinator role (the surfaces, plus Orchestrator) is a coordinator; one whose roles are all focused should stay on its task. Writer (fast small-text generation) and Coder (coding sub-agent) replaced the old single Worker role - a persisted `worker` tag resolves to `coder`. Code: `ProfileRole`, `PROFILE_ROLES` (`packages/protocol/src/personality-schemas.ts`), `PROFILE_ROLE_INFO` (`packages/protocol/src/agent-profiles.ts`). See [agent-personalities.md](agent-personalities.md#roles). Don't confuse with **Mode** (permission level) or provider "categories".
- **Widget** - A fragment of HTML or SVG an agent emits as a `show_widget` tool call, rendered inline in the transcript at that call's position, in a no-network sandbox that can send a message back to the chat (`sendPrompt`) and open a link (`openLink`). Has no file and no life beyond its transcript position - the tool-call input _is_ the content. UI: "Widget" / "Widgets" (the Host settings tool group). Code: `WidgetPayload`, `WIDGET_METADATA_KEY` (`packages/protocol/src/widgets/types.ts`); `normalizeWidgetTimelineItem` (`packages/server/src/server/widget/widget-timeline.ts`). See [widgets.md](widgets.md). Don't confuse with **Artifact** - an artifact is a file-backed document the user keeps, in a side panel; a widget is an inline illustration inside one reply. Forbidden as UI labels: "Visualization", "Inline artifact", "Canvas".
- **Tab** - UI surface representing one chat inside a workspace. Not a conceptual unit; use **Chat** when talking about the model. Code: `WorkspaceTabDescriptor` (`packages/app/src/screens/workspace/workspace-tabs-types.ts`).
- **Terminal** - Workspace-scoped PTY shell streamed over the binary mux channel. UI: "Terminal". Code: `TerminalStreamFrame` (`packages/protocol/src/terminal-stream-protocol.ts`).
- **Script** - One runnable command a project offers, launched from the Play button. Either **declared** (written into the workspace's `otto.json`, persisted, may own a service-proxy route) or **discovered** (read out of the project's own files by a script provider, derived, never persisted). A Script runs in a **Terminal**. UI: "Scripts". Code: `WorkspaceScriptPayload` (`packages/protocol/src/messages.ts`). Forbidden as UI labels, whatever the originating file calls them: "Runnable", "Task", "Run configuration", "Target", "Launch profile". See [scripts.md](scripts.md).
- **Script source** - Where a **Script** came from: either Otto (`otto.json`) or a discovery provider named after the tool and the file it read (`npm · package.json`). Shown as a group header in the Scripts dropdown, never as a second noun for the Script itself. Its `sourceId` also prefixes a discovered Script's wire name (`npm:build`), which is the launch key; the bare name is the display `label`. Code: `ScriptProvider` (`packages/server/src/server/session/workspace-scripts/script-provider.ts`).
- **Service** - A **Script** that is long-running, may bind a port, and carries `health` of `healthy | unhealthy | null` once the daemon has observed it. The only kind a sidebar workspace row reports, because a running plain script says nothing about whether the workspace is up; the row names the service and turns danger when its health fails, and where several run the failing one takes the row's single slot. UI: "Services" in the sidebar's display preferences (**Show → Services**). Code: `selectWorkspaceServiceSummary` (`packages/app/src/components/sidebar/workspace-meta-row/service-summary.ts`), `WorkspaceScriptHealthSchema` (`packages/protocol/src/messages.ts`). Forbidden: "Service" as a label for the Scripts panel, which lists both kinds.
- **Schedule** - Cron-style trigger that creates new agents. UI: CLI/MCP (`otto schedule`, `create_schedule`). Don't confuse with: Heartbeat (cron prompt back into the same agent).
- **Heartbeat** - Cron-style prompt sent back into the same agent/conversation. MCP: `create_heartbeat`. Use for reminders and babysitting where the status should return inline.
- **Orchestration** - UI label for a daemon-owned "Run": one execution of a multi-agent plan. Two flavors: **AI** (an orchestrator-role agent declares typed phases via `start_run` - or the user prompts one from the New Orchestration dialog) and **Graph** (a user-authored deterministic **Graph** executed exactly as drawn; `Run.kind: "graph"`). UI: "Orchestrations" (sidebar entry, page title), "New Orchestration" (dialog). Code stays `Run`/`RunPhase` (`packages/protocol/src/orchestration.ts`), `useRuns` (`packages/app/src/hooks/use-runs.ts`), `runs-screen.tsx`, `runs.*` RPCs - only the user-facing label changed. Don't confuse with **Agent session** (forbidden synonym "Run" there refers to that, not this).
- **Graph** - The reusable template a Graph-flavor **Orchestration** executes: agent nodes carrying roles + prompts, wired by edges, parameterized by declared inputs, with a single Orchestrator root that hosts the chat. Host-level and generic - an orchestration binds a graph to a workspace only at start time; executing a graph starts an orchestration. Authored in the **graph designer** (workspace tab, web/desktop only). UI: "Graph", "Graph designer". Code: `OrchestrationGraph` (`packages/protocol/src/orchestration.ts`), `GraphStore` (`$OTTO_HOME/orchestration-graphs/`), `graph-engine.ts`, tab kind `orchestrationGraph`. See [orchestration-node-capabilities.md](orchestration-node-capabilities.md). Forbidden: "workflow" (that's the Claude provider's Workflow tool), "blueprint", "template" as UI labels.
- **Output fields** - What a Graph node declares it will produce: JSON descriptors (`key`, `type`, `description?`, `required?`) on `GraphNode.output.fields`, never a serialized Zod schema. Present ⇒ the node's agent gets a **submit_output** tool, its result is validated, and downstream nodes receive values instead of prose to re-read. UI: "Output fields". Code: `GraphOutputField` (`packages/protocol/src/orchestration.ts`), `node-output.ts`. See [orchestration-node-capabilities.md](orchestration-node-capabilities.md). Forbidden: "output schema" (the wire never carries a schema).
- **submit_output** - The Otto tool a node's agent calls to deliver its **output fields**. Registered per agent from its labels, so every provider reaches it identically; a validation failure returns a tool error the model corrects in the same session. Code: `registerNodeOutputTool` (`packages/server/src/server/agent/tools/otto-tools.ts`).
- **Condition** (edge) - A JSONata expression on a Graph edge (`GraphEdge.when`), evaluated against the upstream node's **output fields** after it settles. Falsy ⇒ the edge is inactive and its target is **skipped** with reason `condition`. UI: "Condition". Code: `edge-conditions.ts`. Don't confuse with **Gate** (a human approval pause in the AI flavour).
- **Fields carried** - Which of an upstream node's **output fields** an edge delivers (`GraphEdge.fields`). Absent ⇒ all of them. Selection only, never renaming. UI: "Fields carried".
- **Skipped** (node/phase) - A Graph node that did not run because control flow routed around it. Never an error and never silent: `RunPhase.skipReason` says which of `condition` / `upstream-skipped` / `upstream-failed` / `canceled` applied, and the wrap-up names it. Code: `GRAPH_SKIP_REASONS` (`packages/protocol/src/orchestration.ts`). Forbidden: "excluded", "inactive" as the node state.
- **Workspace access** - How much of the workspace one agent session may touch: **Write** (full, the default), **Read only**, or **No workspace access**. Declared per Graph node (`GraphNode.access`) and carried on `AgentSessionConfig.workspaceAccess`. Enforced by withholding tools at spawn, never by prompting; a provider that can't enforce a level (`supportsWorkspaceAccess`, plus `supportsWorkspaceAccessNone` for the "none" tier) refuses the node rather than running it with a weaker boundary. UI: "Workspace access". Code: `packages/server/src/server/agent/workspace-access.ts`. See [orchestration-node-capabilities.md](orchestration-node-capabilities.md). Don't confuse with **Mode** (provider permission level) or Codex's `sandboxMode` (one provider's native tiers, which this maps onto). Forbidden: "sandbox mode" as the Otto-wide label.
- **Query tools** - Author-defined read-only lookups available only inside one Graph node's session: `command` (argv only, no shell), `http-get` (no custom headers), `file-read` (inside the run's cwd). Registered as `query_*` so they can never shadow a built-in Otto tool. UI: "Query tools". Code: `node-query-tools.ts`. Forbidden: "data tools".
- **Retry** (node) - Bounded re-dispatch with backoff after a _failed_ attempt (`GraphNode.retry`). Distinct from **Loop**, which re-runs work that succeeded but wasn't good enough. Every attempt counts against the run's agent cap.
- **Time limit** (node) - Wall-clock ceiling for one attempt (`GraphNode.timeoutMs`). On expiry the agent is really canceled, the phase is marked `timedOut`, and the node fails. Forbidden: "timeout" as the UI label.
- **Prompt template** - A host-level reusable prompt stored at `$OTTO_HOME/prompt-templates/`, bound to a node via `GraphNode.promptTemplate`. A **snippet** (`snippet: true`) is a template other templates include. UI: "Prompt template" / "Snippet". Code: `prompt-template-store.ts`, `prompt-render.ts`. Forbidden: "partial" (EJS jargon).
- **Mode** - Provider-specific operational mode (plan, default, full-access, …). UI: icon-only. Code: `modeId` in `AgentSessionConfig` (`packages/protocol/src/messages.ts`). Don't confuse with **Interface mode** (client display depth).
- **Interface mode** - The device-local display depth: **User** (a reduced view for chatting with agents and organizing projects - developer tools like files, diffs, terminals, git, and search are hidden) or **Developer** (the full environment, identical to today's app). Presentation only - never synced to the daemon, never changes what agents can do. UI: "Interface mode" (Settings → General; chosen first in the setup wizard) - always that two-word label, never bare "mode". Code: `interfaceMode: InterfaceMode | null` in `AppSettings` (`null` ⇒ Developer), gate `useIsDeveloperMode()` (`packages/app/src/hooks/use-interface-mode.ts`). See [onboarding.md](onboarding.md). Forbidden labels: "Simple mode", "Basic mode", "Pro mode". Don't confuse with **Mode** (provider operational mode).
- **File view mode** - How one file tab presents its content: **Editor**, **Editor and preview** (the split), or **Preview**. Exactly three, exactly one selected, remembered per file. UI: the icon mode bar at the right of the file tab's toolbar. Code: `FileViewMode` (`packages/app/src/stores/file-view-store.ts`), `FileViewModeBar` (`packages/app/src/components/file-view-mode-bar.tsx`). See [text-editor.md](text-editor.md#the-unified-file-tab-and-view-modes). Don't confuse with **Formatted**, which shares the bar but is not one of these. Forbidden as UI labels: "Source", "Raw", "WYSIWYG" for any of the three.
- **Formatted** - Markdown live preview: the editor hides markers on every line except the one holding the caret, so the document reads as formatted text while remaining the exact text on disk. Governs the **editor pane**, so it is live in both Editor and Split, and inert (visible, disabled) in Preview. Defaults on; device-local and global, not per file. UI: "Formatted", tooltip "Formatted markdown", the trailing segment after a divider in the file view mode bar. Code identifiers stay historical: `markdownLivePreview` (`packages/app/src/editor/editor-prefs-store.ts`), `markdownLivePreviewExtension` (`packages/app/src/editor/markdown/markdown-live-preview.ts`). See [text-editor.md](text-editor.md#three-modes-and-one-axis). **Never a UI label: "Live preview"** (the bar already has a mode called Preview), "WYSIWYG", "Rich text", "Hide markdown markers". Don't confuse with **File view mode**: this is an orthogonal axis, never a fourth mode.
- **Effort** - How hard the model reasons before answering; one concept across all providers even though vendors brand it differently (Claude "thinking", OpenAI "reasoning effort") and option sets vary per model/provider (on/off, low/medium/high, …). Options are advertised per model via `thinkingOptions` on `AgentModelDefinition`; never force a fixed option set. UI: "Effort" / "Select effort" everywhere (composer control, schedule form, artifact form). Tooling/prompts request effort via the canonical level scale `off < minimal < low < medium < high < xhigh < max`, resolved to the nearest option the target model supports (`resolveEffortOption`, `packages/server/src/server/agent/effort-levels.ts`); exact option ids always win, keeping provider-special options (Claude `ultracode`) reachable. Code identifiers are historical and stay: `thinkingOptionId`, `thinkingOptions`, `thinkingByModel`, i18n keys `agentControls.thinking.*`, testIDs `*-thinking-*`. Forbidden as UI labels: "Thinking", "Reasoning". Don't confuse with **reasoning blocks** (the chain-of-thought text an agent streams, e.g. the "Always expand reasoning" setting - that stays "reasoning").
- **Attachment** - A PR or issue bound to an agent prompt, from any configured **git provider** (GitHub or Bitbucket Cloud). UI: "Attach issue or PR". Code: `AgentAttachment` (`packages/protocol/src/messages.ts`); provider-neutral kinds `hosting_pr` / `hosting_issue` (each carries a `provider`), with legacy `github_pr` / `github_issue` still accepted. See [git-providers.md](git-providers.md).
- **Composer** - The whole prompt surface for sending work to an agent. Code: `Composer` (`packages/app/src/composer/index.tsx`). Don't call this "message input" except for the text-entry subcomponent.
- **Composer input** - The text-entry surface inside the composer. Code: `MessageInput` (`packages/app/src/composer/input/input.tsx`).
- **Composer toolbar** - The bottom control row inside the composer input. Contains agent controls, attachment button, voice controls, and stop/send controls. Code: `leftContent`, `beforeVoiceContent`, and `rightContent` slots in `MessageInput` (`packages/app/src/composer/input/input.tsx`). Forbidden: "Status bar".
- **Agent controls** - Provider, model, mode, thinking, and provider-feature controls for an agent or draft agent. Code: `AgentControls` / `DraftAgentControls` (`packages/app/src/composer/agent-controls/index.tsx`). Forbidden: "Agent status bar".
- **Composer footer** - Optional area rendered below the composer input but still inside the keyboard-shifted composer layout. Code: `Composer.footer` (`packages/app/src/composer/index.tsx`).
- **Composer track** - A contextual lane above the composer input. Specific tracks use the `<thing> track` form: **Queue track**, **Subagents track**, **Background Tasks track**. Code: queue track inside `Composer` (`packages/app/src/composer/index.tsx`), `SubagentsTrack` (`packages/app/src/subagents/track.tsx`), `BackgroundTasksTrack` (`packages/app/src/background-tasks/track.tsx`).
- **Queue track** - The Composer track listing messages parked to run as the agent's next turn. Row actions are Edit (pull it back into the composer input) and Send now (run it immediately, interrupting). Backed by the daemon when the host advertises `features.steerQueue`. Code: queue track inside `Composer` (`packages/app/src/composer/index.tsx`), `useComposerQueue` (`packages/app/src/composer/queue.ts`). Forbidden: "pending messages", "message buffer".
- **Delivery** - How a prompt reaches a **busy** agent: **Interrupt** (cancel the in-flight turn, run now) or **Queue** (let it finish, run next). Exactly two values, used everywhere: Settings → Default send, the `delivery` wire field, and the `send_chat_prompt` tool arg. Against an idle agent both mean "run now". Code: `AgentPromptDelivery` (`packages/protocol/src/messages.ts`), `startAgentRun` (`packages/server/src/server/agent/agent-prompt.ts`). See [chat-lifecycle.md](chat-lifecycle.md#delivery---how-a-prompt-reaches-a-busy-agent). Forbidden as synonyms: "steer mode", "send mode", "append".
- **Background Tasks track** - Lists background shell processes a provider launched itself (Claude Bash tool `run_in_background`) - plain shell commands, never AI subagents. Renders independently of and alongside the Subagents track; a row's actions are Stop (while running) and Clear (once terminal). Code: `BackgroundTasksTrack` (`packages/app/src/background-tasks/track.tsx`). Forbidden: "background jobs", "shell tasks", "background agents" (implies AI).
- **Attachment tray** - The selected-attachments row inside the composer input, above the text input. Code: `renderAttachmentTray` (`packages/app/src/composer/index.tsx`). Forbidden: "Attachment bar".
- **Fork** - Starting a NEW chat seeded with a copy of another session's curated history. The history rides along as a `chat_history` composer attachment on a draft; the fork does **not** resume or branch the provider-side session, and the source session keeps running untouched. Two targets, one surface, one RPC (`agent.fork_context`, gated on the `agentForkContext` host feature). UI: the fork menu lives in the assistant turn footer and offers "Fork in a new tab" / "Fork in a new workspace". On a **completed** turn it sits beside the copy button and pins a boundary to that turn, so the fork stops where the turn ended. On the **in-flight** turn it sits beside the progress loader and elapsed timer, and omits the boundary entirely: `selectForkContextRows` projects the whole timeline when no boundary is given, so the fork captures everything up to now, including the response still streaming. That omission is what makes mid-run forking work; pinning a boundary there would silently drop the live response. Forbidden on provider-subagent (read-only) panes. Code: `useForkAgent` (`packages/app/src/hooks/use-fork-agent.ts`), `selectForkContextRows` (`packages/server/src/server/agent/activity-curator.ts`). Don't confuse with: git fork (unrelated; Otto has no such concept), **Worktree** (filesystem isolation, not history copying).
- **Conflict** - Two distinct senses; do NOT use the bare word in UI copy without qualifying which: (a) **stale-write conflict** on `otto.json` ("Config changed on disk", code `stale_project_config`, `packages/app/src/screens/project-settings-screen.tsx`); (b) **git merge conflict** (no current UI string).
- **Total tokens** - Lifetime token **spend**: everything billed across a chat's whole run, including every input class and output. Σ over the chat and everything spawned under it is **the** chat total (`selectChatTotals`, `packages/app/src/subagents/chat-totals.ts`); per agent it is `cumulativeTokens` / `cumulativeUsage`. Only ever grows. UI: "total tokens" / "total". Code: `AgentCumulativeUsage` (`packages/protocol/src/messages.ts`), `turn-usage.ts` (`packages/server/src/server/agent/`). See [subagent-accounting.md](subagent-accounting.md#chat-totals-one-honest-number-per-chat). **Never** use for context occupancy - the two share no units. Forbidden: "tokens used", "context tokens".
- **Context** - Context-window **occupancy**: how full the model's window is right now. Goes down when compaction runs. Reported per category by `agent.context.get_usage`; rendered by `context-window-meter.tsx` and `context-management/summary.tsx`. UI: "context". Code: `contextWindowUsedTokens` / `contextWindowMaxTokens` on `AgentUsage`. **Never** mix into the same readout as **Total tokens** - conflating occupancy with spend is why the cost numbers used to feel wrong. Forbidden: "total tokens", "tokens spent" for this concept.
- **Cost** - A dollar figure reported by the provider or calculated at its provider boundary from its published token rate card (see the pricing invariant in [subagent-accounting.md](subagent-accounting.md#pricing-invariant-the-a-provider-with-claude-in-it-trap)). A provider that cannot price its own work (a local model, most OpenAI-compatible endpoints) shows a **blank**, not an estimate. Where only part of a tree was priced, the figure is a floor and is shown as `≥ $X`. Code: `costUsd` / `costCoverage` on `AgentCumulativeUsage`. Forbidden: "estimated cost", "~$" as a UI affordance.

## Inconsistencies (documented, not papered over)

- CLI `--host <host>` description `"Daemon host target"` (`packages/cli/src/utils/command-options.ts`) blurs daemon/host; the app keeps them distinct.
- `WorkspaceDescriptorPayloadSchema.workspaceKind` accepts legacy `"checkout"` on the wire (`packages/protocol/src/messages.ts`) while `PersistedWorkspaceKind` does not (`packages/server/src/server/workspace-registry-model.ts`).
