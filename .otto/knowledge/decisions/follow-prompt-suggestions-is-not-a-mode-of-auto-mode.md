# Follow prompt suggestions is not a level of Auto mode

<!-- compiled_truth -->

"Follow prompt suggestions" accepts an already-generated next-prompt suggestion on the user's behalf. It is surfaced per chat as **Autonomous mode**, and it is deliberately not a level, variant, or special case of Auto mode; the two share no code.

The boundary is a difference in what is being decided. Auto mode governs how an agent decides to act **inside** a turn: which tools it may run without asking, and how permission prompts resolve. Autonomous mode governs one thing **between** turns: who accepts the ghost-text suggestion the agent already produced, the user pressing Tab or the app. Everything the agent then does once that prompt is sent is still governed by Auto mode, unchanged. Folding it into Auto mode would collapse two different questions into one dial and make "off" ambiguous.

Concrete consequences that hold the boundary:

- **Per-chat control.** A toggle (Material `autoplay` icon, tooltip "Autonomous mode on/off") sits at the message box's top-right, rendered beside the text input rather than over it. State lives in the device-local app setting `agentFollowPromptSuggestions`, keyed `serverId:agentId`, and is managed in `packages/app/src/composer/follow-suggestion/setting.ts`.
- **Seeded once, then independent.** The device-local `followPromptSuggestions` setting (default off) is only the starting value for a chat. A chat is seeded the first time its composer shows the toggle, and stores `false` as well as `true`, so changing the default never flips existing chats. A successful archive deletes the chat's entry, so an unarchived chat starts from the default again.
- **Only where it can act.** The toggle renders only in Chat mode, while AI prompt suggestions (`promptSuggestionsEnabled`) are on, and for chats whose provider advertises the `supportsPromptSuggestions` agent capability. Claude (and the E2E mock provider) set it. Codex does not: its app-server protocol has no suggestion event. A dependent control that cannot act reads as broken rather than unavailable.
- Nothing in `packages/app/src/composer/follow-suggestion/` reads or writes a permission mode, and nothing in the permission-mode path reads these settings.
- Off is inert: no sends and no band. Turning a chat off clears its chain state, so turning it back on starts from zero.

Two properties the feature must keep, because they are what stops autonomous self-prompting from feeling out of control:

- **A user-chosen bound.** The "Suggestions in a row" setting (`followPromptSuggestionsLimit`: 3, 5, 10, 25, or Unlimited; default 3) caps consecutive followed suggestions per chat. The count resets only when the user sends a message of their own. Unlimited is an explicit opt-in that follows until the agent stops suggesting; the default stays conservative. The rule is one pure function, `decideFollowPromptSuggestion` in `decide.ts`, where a `null` bound means unlimited.
- **Visibility.** An auto-accepted prompt lands in the transcript looking exactly like a typed one. A purple `FlyoutBand` above the message box states that Otto is following the agent's suggestions, counts them ("N of M sent", or "N sent" when unlimited), and its dismiss control turns Autonomous mode off for that chat.
