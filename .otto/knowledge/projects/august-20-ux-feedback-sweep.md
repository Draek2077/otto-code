# August 20 UX feedback sweep

<!-- compiled_truth -->

## Objective

Resolve a batch of thirteen UX and reliability reports raised on 2026-08-20, spanning chat transcript position, history loading, explorer sidebar performance, diff and review chrome, file editor preview search, meeting notes, background tasks, Zoom presence, and two new capability requests.

This is a successor batch to [[august-ux-reliability-bug-sweep]], not a continuation of it. The chat-position report overlaps that page's replay/grouping criterion, which means the earlier fix either did not cover scroll offset or has regressed.

## Workstream A: chat transcript position (three reports, one subsystem)

The dominant cluster. All three are governed by `docs/chat-scrolling.md`: while the reader holds the position the app writes nothing, and detach is decided from the scroll event.

- **A1. Tab return loses the position.** Scroll up in a chat, leave the tab, come back, and the transcript is not where it was left. Reported as repeated, not occasional. User hypothesis, unverified: the replay of messages on remount changes content height under a restored offset.
- **A2. Detached viewport bounces during live activity.** When scrolled up and no longer following, continued activity at the bottom that edits the document makes the viewport bounce. A detached reader must receive no writes at all, so any movement here is a contract violation.
- **A3. Followed chats return to a constant wrong location.** While attached at the bottom, leaving the window and returning lands the transcript at a location that appears random but is reproducibly the same, regardless of where the chat was left. The stability of the landing spot is the diagnostic signal: it suggests a fixed offset or a pre-measurement layout pass, not a race.

**Discipline for this workstream:** one change at a time, verified in the running app between each. Batched scroll fixes have passed tests and still broken the surface, and `strategy-web` unit tests do not catch it.

## Workstream B: scroll is held during history loading

While history is loading, page content cannot be scrolled. It behaves as though the load holds the surface. Determine whether this is an explicit scroll lock, a blocking overlay, or main-thread starvation, then let the reader scroll during the load.

## Workstream C: explorer sidebar open/close performance spike

Opening and closing the explorer sidebar produces a clear spike of slow communication and dropped FPS on large work projects. Reported from real work repositories, so repository scale is part of the reproduction. Measure before changing anything, and record the numbers.

## Workstream D: diff viewer does not wrap in the sidebar

Wrapping fails on the diff viewer itself rather than on its container. Scope the fix to the diff renderer, honoring [[diff-renderer-structural-parity]].

## Workstream E: delete all review comments

Comments can be left on files the user can no longer locate, with no way to clear them in bulk. Add a "delete all comments" action reachable from Changes, with a destructive confirmation that states the scope being cleared.

## Workstream F: search inside file editor Preview

Preview in the file editor must support search within the previewed content, with matches highlighted the way the normal editor highlights them. Reuse the editor's existing search and highlight primitives rather than building a second search path.

## Workstream G: meeting notes popup pins its header

The top section of the meeting notes popup must stay pinned while the entry list scrolls, so the header remains visible throughout.

## Workstream H: "Follow your own suggestion" autonomy toggle

A new opt-in mode: when a suggestion for the next prompt exists, take it immediately and automatically. This is explicitly **not** Auto mode and must not be folded into it. It governs only the acceptance of an already-generated next-prompt suggestion, and needs its own setting, its own copy, and a clear off state.

## Workstream I: status glow behind workspace notify icons

The three workspace icons that signal green, amber, and red should carry a pulse glow behind the icon to draw attention. Animated when animations are enabled; when animations are off, fall back to a static glow rather than nothing.

## Workstream J: background tasks clear only while the popup is closed

Automatic clearing of completed and failed background tasks must be suppressed while the background tasks popup is open, so the user can deal with entries they are actively looking at. Settings copy for `autoClearCompletedBackgroundTasks` and `autoClearFailedBackgroundTasks` likely needs rewording to state the new condition.

## Workstream K: Zoom offline keeps its icon

Going offline in Zoom currently removes the whole icon. Offline is a state of the icon, not the absence of one, so the icon must remain and render its offline presence.

## Acceptance criteria

- A chat returns to the exact position it was left at, whether the reader was scrolled up or following the bottom, across tab switches and window blur/focus.
- A detached reader receives no scroll writes during live activity, including document-editing activity at the bottom.
- Content scrolls freely while history loads.
- Explorer sidebar open and close carries no measurable FPS or communication spike on a large repository, with before and after numbers recorded.
- The sidebar diff viewer wraps its own content.
- Changes exposes a confirmed bulk delete for review comments that states its scope.
- File editor Preview supports search with highlighted matches, using the editor's existing primitives.
- The meeting notes popup header stays pinned while entries scroll.
- A separate, off-by-default autonomy toggle instantly accepts an existing next-prompt suggestion, independent of Auto mode.
- The three workspace notify icons show a pulse glow when animations are on and a static glow when they are off.
- Background task auto-clear is suppressed while the popup is open, and the settings copy says so.
- Zoom offline renders an offline icon rather than removing it.

## Constraints

Honor `docs/chat-scrolling.md` for every workstream A change, and keep those changes serialized and individually verified. Preserve provider-neutral behavior, documented UI primitives and theme tokens, and backward-compatible wire contracts. Treat each report as an unverified observation until reproduced, and separate observation from hypothesis in every handoff.
