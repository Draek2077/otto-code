# Outcome

Restore the selected F04 Project Knowledge family on clean Paseo through Otto-owned daemon storage, contracts, supported plugin UI and provider-neutral tools. Historical behavior is described in [[project-knowledge-context-management]]; it is not proof of availability in Otto 0.10. F05 Context Management, provider prompt composition, Brain, and Kanban are outside this charter.

## Delivery slices

1. **K01: owned storage/service foundation, integrated; final release gates open.** Resolve project override before an existing repository store before host default. Consume a daemon-resolved canonical project ID/root and retained host-directory identity through injected ports. Read canonical 0.9 Markdown without implicit migration; create drafts; append evidence; require digest-pinned truth updates; demote changed confirmed truth; retain unknown fields; preserve corrupt files. Acceptance requires isolated repository/host fixtures, stale and competing writer tests, path-boundary and root-preservation tests, typecheck/lint/format, normal commit hooks and exact-source required CI/build evidence. A standalone library does not satisfy an end-user journey.
2. **K02: explicit store and format migrations.** Preserve original identities, recovery copies, user roots, unknown fields and layout. No silent relocation or automatic installed-data rewrite. Prove interrupted/conflicting migration recovery with isolated old-store fixtures.
3. **K03: six source-backed roots and bootstrap.** Background, Architecture, Flow, Mindmap, Stack, Roadmap. Deterministic source-backed drafts, idempotence, sparse/corrupt input handling and no invented root review lifecycle. Never overwrite user-authored roots.
4. **K04: full rich record operations and human review.** Proposed/confirmed/superseded lifecycle; reason-bearing truth updates; append-only evidence; charters/delivery/progress; references/dispositions. Only an explicit human action confirms a conclusion. Changed confirmed conclusions return to Draft.
5. **K05: Desktop/Mobile management UI and typed plugin RPC.** Reachable host/project-scoped list/read/create/edit/review, honest update-host gating, Paseo controls, explicit storage choice and recovery. Parent owns coordinated shared project/host SDK contracts; this feature does not add generic metadata or navigation seams independently.
6. **K06: assessed MCP operations and demand-driven compact catalog.** Confirmed-page/root discovery, on-demand bodies, optional policy pointer, bounded metadata output. No automatic full-root injection or restoration of deferred provider/context composition.
7. **K07: external refresh and recovery.** Daemon-owned observation, invalidation after atomic writes, external editor/Git changes, deleted selection handling, conflict-safe retry and explicit abandoned-lock recovery. A fresh read alone does not prove open-surface refresh.
8. **K08: complete feature acceptance.** Review every selected capability with exact-source CI/build evidence, Desktop/Mobile journeys, compatibility fixtures, documented provider/host limits, and sequential reviewed integration into otto-0.10/phase-0. Each earlier slice has its own checks; this final review cannot substitute for them.
