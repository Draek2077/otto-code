# Running-agent capture: severe frame stalls, animation churn, and missing script attribution

<!-- compiled_truth -->

The installed Otto 0.9.5 capture from 2026-09-10 17:11:01 to 17:38:58 UTC confirms repeated severe UI frame stalls while the user reports three agents running across three workspaces. The end diagnostic reports four running agents, so concurrency was not constant across the recording.

Across 170 resource samples (about 28 minutes), 2,129 counted frame gaps exceeded 50 ms; 167 sample windows included a gap of at least 100 ms. The ordinary sampler peaks at 750.1 ms and excludes gaps of at least one second. The retained Long Animation Frames entries independently include 1,622 ms and 1,092.1 ms frames. Thus average FPS conceals substantial stutter.

The capture records 2,351,679 DOM mutations, about 1,403 per second. Its final 300 mutation batches cover only 3.365 seconds: 9,014 of 9,207 records are style attributes, and 8,994 records are attributed to working spinners, running workspace indicators and four agent tab ancestors. Source inspection routes those indicators to BlobLoader. This is a concrete animation-work lead, not proof that animations caused the large stalls. The capture-scoped MutationObserver also processes this traffic; its overhead was not measured.

Inbound handling grew by 2,563 ms over about 1,676 seconds (0.153% of elapsed time). This covers synchronous handling, not downstream React rendering. The three longest saved frames have no matched inbound dispatch. In the final 200 long frames, style/layout totals 589.1 ms against 32,387.5 ms frame duration. These measurements do not identify the unaccounted time as a specific JS function, GC, GPU contention or operating-system scheduling.

Client heap ranges approximately 317-438 MiB against a 4 GiB limit, and the end system diagnostic reports 30.8 GiB free of 63.1 GiB. Memory exhaustion is not supported. DOM nodes and query observers increase but chats and retained streams also increase, so the recording does not prove a leak.

Attribution limitations: all 200 saved long-frame entries have empty scripts arrays and the script aggregate is empty. The entries cover only the final 209.793 seconds; DOM attribution covers only the final 3.365 seconds. The pre-capture history has two samples and an invalid negative trend elapsedMs, so it cannot support an hours-long degradation conclusion. The cause of missing script attribution remains unverified.

Next diagnostic experiment: compare the same running workload with and without animated indicators, measuring frame stalls and capture-observer overhead; obtain renderer CPU attribution if stalls persist. No remediation or runtime experiment was performed in this investigation.
