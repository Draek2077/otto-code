# Otto 0.10 testing-readiness and basic UI structure review

## Scope and method

This is the basic review Philippe requested before his own UI review. It audits feature-level integration and proof, not every changed line or a completed usability test. Source: clean reconstruction checkout on `otto-0.10/phase-0`, application head `e9cc4d3ed3f7bb9cd88e751dad2f147947561f14`; released reference `v0.9.35` / `9b281ec547741b2309bae804f8b3841c32369aaf`.

Reviewed the master’s 22 feature families and retained later-work list, relevant software guides and feature charters, registration/composition paths, source boundaries, current CI/build evidence, and 14 saved CI screenshots across nine surface families. The visual sample comprises Knowledge, Context, Artifacts, Brain, Kanban, Workflows, Visualizer, Architectural Views and OpenAI-compatible setup; ten captures are wide and four compact. Some are intentionally scrolled, conflicting or failed-fixture states. They are not evidence that those fixture errors occur on a normal user host. Old Knowledge/Context layout contracts were checked in released source; no old/new app, daemon or model was launched for comparison.

## Verified position

- The application baseline passed full CI 43266928686 (21/21), Otto App Acceptance 43266923452 (46+44=90), and Editor Runtime Acceptance 43266923668. Desktop, Android APK+AAB, Docker and Nix build-only results are recorded in the master with their source-equivalence boundary. Green functional tests do not establish that the UI is good or accepted.
- The selected implementation families are integrated; F22 provider-only older-history recovery remains missing. Brain/local Remote operation, Knowledge/filesystem limits, Context’s separately parked isolation investigation, GitHub/Jira and Bitbucket live permissions, vendor Connector access, speech/native-device behavior and personal terminal/editor setup retain their existing gates.
- The four former Brain UI/TUI, Knowledge and Kanban child directories no longer exist and are absent from Git’s active worktrees. Their feature owners are integrated. The reconstruction checkout remains necessary. Three unrelated older agent worktrees were preserved.
- The canonical Knowledge store is still the main checkout’s shared `.otto/knowledge` tree. Its pending files must not be swept or reset while organizing the integration branch.
- Several planning displays describe history rather than current implementation: Artifacts’ 0/5 counter explicitly measures old 0.9 slices; Brain’s 5/10 counts accepted checkpoints and does not mean half the app is absent. Separate implementation, automated verification, product/UI acceptance and release gates.
- Documentation cleanup corrects Brain’s inclusion in the eight-package publication order, Windows dev home/port and launcher instructions, and stale statements that Context and the File Editor are still waiting to return. No publication or runtime change is part of that cleanup.

## Review criteria from Philippe

Look for bad layout, wasted space, superfluous or duplicated presentation, overly long pages, weak categorization/grouping and controls that hide the working task. Check desktop and compact separately. Use the released 0.9.35 working flows as a reference, current Paseo controls/architecture as the integration contract, and preserve user preferences and drafts.

Philippe owns final UI judgement when he reviews the app. A whole-interface rollback, old chat/session machinery, broad themes/icons, or a new generic pane system has not been selected. If he chooses a different layout, implement one accepted feature surface at a time through Otto-owned files and marked seams.

## Testing transition

The current master charter remains the sole progress/task plan. It records source identity, green automation, Philippe’s UI review, data/upgrade checks, functional pilot journeys, native/account acceptance and performance/regression gates. This finding supplies the audit evidence and basic observations; it is not another task registry.

The development source remains the existing reconstruction checkout, not frozen 0.9.35 `main`. Verify branch, revision, printed daemon endpoint and runtime home before testing. Existing dev defaults use checkout-local state and port 6788; installed Otto on 6868 remains outside this effort.
